# P007 四角色任务卡 V2 与双重设计门禁

## 目标

将 P007 的单一通用任务卡替换为设计、前端、后端和 QA 四套专用模板。涉及体验变更时，设计先提交三套实际方向图供用户选择；方向明确批准后才进入 Figma 完善，最终 Figma 再次批准后才允许前后端实现。

## 实施规则

- 设计阶段完成视觉侦察、反公式化约束和三个差异明显的方向；每个方向必须有可直接比较的实际图片，不能只交文字、色板或参考链接。
- 方向图保存在 `.planning/dispatch/<goal-id>/artifacts/design-directions/` 并在用户对话中展示。方向批准前不得调用 Figma，也不得修改业务代码。
- 方向获批后，设计角色在 Figma 中完善高保真页面、组件、状态、响应式和交互规范；记录文件 URL、节点 ID 和第二次人工批准证据。
- 前端与后端只有在最终 Figma 获批后才可写业务代码；等待期间后端只能只读侦察和拟定接口契约。
- 前端提供实现截图并对照 Figma；QA 独立核验两次批准证据、视觉还原、响应式、交互、无障碍和反公式化要求。

## 状态与文件

- 四套任务卡模板是唯一卡片来源，保存在总指挥技能的 `assets/cards/`。
- manifest 分别记录方向图、选定方向、方向批准、Figma 文件/节点和最终批准。
- 临时卡片、方向图和报告保存在 `.planning/dispatch/<goal-id>/`；永久规范保存在 `docs/specs/`。
- 两个审批阶段均使用 `waiting_human`，不得把沉默或一般性回应视为批准。

## 验证

- 角色模板字段和角色专属要求通过确定性校验。
- 方向图不足三张时不能请求审批；方向未批准时不能使用 Figma；最终 Figma 未批准时前后端不可写。
- 保持肯定式“编队执行”触发、独占路径、最多三个专业代理和两轮返修上限不变。
- 运行 `node --test tests/native-team-workflow.test.mjs`、`npm test` 和 `npm run lint`。

## 边界

- 本计划不创建 Goal、任务卡实例或子代理，不调用 Figma，不修改业务页面，不推送、合并、建 PR 或部署。
