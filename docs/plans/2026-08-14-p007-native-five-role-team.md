# P007 Codex 原生五角色编队与 P010 Linear 中央化

## 目标

在 P007 建立总指挥、设计、前端、后端、测试五个仓库技能。只有用户发出肯定式“编队执行”时才启动团队；角色按任务自适应启用，每张任务卡使用新代理，总指挥负责共享文件、集成、Git 和发布边界。

Linear/Symphony 作为备用入口保留，但所有工作流、注册和运维配置集中到 P010，默认停止。业务项目不再保存 Symphony 工作流或专属校验器。

## 已确认规则

- 总指挥使用 Sol + Ultra；设计和测试使用 Sol + High；前端和后端使用 Terra + High。
- 同时最多三个专业代理。每张新卡使用新代理，返修恢复原卡代理。
- 涉及体验变更时启用设计，设计稿必须人工批准。等待期间后端只能只读侦察，前后端不得写业务代码。
- QA 独立验收，最多两轮“原责任人修复、QA 复验”。
- 子代理不得提交、推送、创建 PR、合并、部署、修改共享契约或触碰生产数据。
- 单独显式调用角色技能可以完成该层任务，但不能创建其他代理或越层。

## 交付结构

- 五个技能位于 `.agents/skills/`，均关闭隐式调用。
- 每次编队在被 Git 忽略的 `.planning/dispatch/<goal-id>/` 保存 manifest、角色卡和报告。
- 角色卡必须包含目标、输入、拥有路径、只读路径、技能、契约、交付物、验收、验证、禁止事项和依赖。
- 重要设计规范保存到 `docs/specs/`；本计划保存于 `docs/plans/`。

## Linear 中央化

- 先通过 P010 受控停止 P007，不删除 S002、TIM-6 workspace、日志、锁或凭据。
- P007 删除 `WORKFLOW.md` 和 Symphony 专属校验器；普通 CI 继续提供必需 job `verify`。
- P010 的八个登记项目全部指向 `ops/workflows/<Pxxx>/WORKFLOW.md`；P007 保留 pilot 标识但设置为 disabled。
- 只有启用项目要求中央工作流实际存在并通过校验。恢复时必须显式启用、doctor、start。

## Git 与发布边界

- P007 从最新 `origin/main` 的独立 worktree 实施；P010 从本地部署分支的独立 worktree 实施。
- 两个仓库独立验证和提交，不自动推送、建 PR、合并或部署。
- CloudBase 正式发布只能在目标提交合并回干净的本地 `main` 后，从 `main` 重新构建并发布。

## 验收

- 五个技能通过官方 quick validator。
- 自动测试口令识别、自适应角色、设计门禁、独占文件所有权和两轮返修上限。
- P007 通过完整 `npm test` 与 `npm run lint`，远端必需检查仍为 `verify`。
- P010 通过完整运维单元测试；所有登记路径位于 P010；P007 显示 stopped/disabled。
- S003 仅在确认干净且已合并后移除；S002 与 TIM-6 内容保持不变。
