# CloudBase 发布门禁

本文件是 P007 仓库 CloudBase 正式发布的唯一规则权威；`AGENTS.md` 与总指挥技能只保留入口引用，不在别处重复本门禁。

## 发布入口与顺序

- 正式发布只能从本地 `main` 分支执行；不得直接从任务分支或 worktree 构建、上传正式环境。
- 固定顺序：在任务分支或 worktree 完成修改、验证和提交 → 合并回 `main` → 确认 `main` 已包含目标提交且工作区没有本任务未提交改动 → 从 `main` 重新构建发布产物 → 发布并进行线上验收。
- 如果合并被阻塞、`main` 未包含目标提交，或 `main` 存在会污染发布产物的未确认改动，必须暂停并向用户说明；不得以直接从任务分支发布作为绕过方式。

## 增量构建与全量授权

- 正式发布默认只做增量构建。构建前必须先运行 `npm run build:changed -- --dry-run` 核对计划。
- “发布所有项目”或“发布本地所有项目”只表示完整汇总、上传和验收全部线上入口，不构成全量重建授权。
- 如果 dry-run 因根 `package.json`、构建脚本、无效基线或其他原因计划全量构建，必须在开始安装依赖或构建前暂停，说明触发原因和预计范围；只有用户明确回复“确认全量构建”后，才允许运行 `npm run build:cloudbase`、根 `npm test`、`--force` 或其他会安装/构建全部子项目的命令。
- 未获全量授权时，应按 Git 差异只测试和构建实际受影响的子项目，再运行 `npm run assemble:cloudbase` 和根静态集成测试；如果根级改动是否影响其他子项目无法可靠判定，必须暂停询问，不得以“安全起见”为由自动全量。

## 运行时

- 发布构建使用 NVM 的 Node.js 22；本机缺少时运行 `nvm install 22` 后 `nvm use 22`。
- 不得用临时 `npx node@22` 替代项目运行时，也不得擅自修改 NVM 默认版本。
